# Delivery Summary — configurable distillery and remote training

plan: `configurable-distillery-and-remote-training` · run: `complete` · date: `2026-10-17`
baseline: `devague summary skeleton`

## Intent

> jev distill runs with the models an operator actually has: a configurable student profile, Clef as the teacher in whichever build variant the operator serves (BF16, NVFP4, FP4, W4A16 and so on), optional secondary roles (alt teacher, the deployment board, edge) and a deployed format declared in the pre-registration (a quant or bf16). The training step runs through an executor seam that is agnostic to where the job runs, so a later session can add SageMaker (us-east-1) without touching the stages.

After: An operator writes a run.toml that names a student profile, the Clef variant and its serving recipe, which secondary roles are present, the deployed format (quant or bf16) in the pre-registration, and the executor (local by default). Every stage then runs, and every bar is computed or reported not applicable with a reason. A later session can add a SageMaker executor by implementing the seam alone, with no stage edits.

## Mid-work Decisions

- `d1` — t6 acceptance criterion 1 is met only for pointer/`__init__.py`; serve.py, quantized.py and `train_distill.py` still import generic distill code (systemone.SystemOneClient, envs.EnvSpec, executor, prereg). Add a decoupling task (d-t16) that runs after t12 and before t13/t14: move SystemOneClient and EnvSpec into a shared module outside `jev_factory`.distill (re-exported from their old distill paths for compatibility), and have `train_distill`.`run_train` and `resolve_hyperparameters` receive the executor and the pre-registration as arguments instead of importing them. Acceptance: the AST guard in tests/`test_backbone_pointer.py` allows no distill imports anywhere in `jev_factory`/backbones/pointer (the `_KNOWN_DISTILL_IMPORTERS` list is emptied), the full suite and the golden test pass, and existing import paths keep working. — Removing the three remaining imports means moving the wire client and EnvSpec and inverting `run_train`'s dependency on executor and prereg, which touches files t7, t10 and t12 own. Doing it inside t6 would collide with them; the operator chose a separate task after t12 over narrowing the criterion.
- `d2` — t11's summary promised the distill stages reach the student via registry.get(profile.backbone), but the Backbone protocol (backbones/base.py) has no layout, serve or `run_train` hooks, so train.py still imports backbones.pointer layout, serve and `train_distill` directly. The d1 decoupling task (d-t16, after t12) is extended: it also adds the needed hooks to the Backbone protocol (layout and config file names, serve argv, train plan and run), implements them on PointerBackbone, and switches the distill stages (train.py and any pipeline call sites) to registry.get(profile.backbone). Added acceptance: an AST test shows no module in `jev_factory`/distill imports `jev_factory`.backbones.pointer directly, except through the registry. — A clean registry swap needs a protocol extension that touches backbones/base.py, pointer/`__init__.py` and the pipeline wiring t12 owns; the operator chose to fold it into the d1 task rather than defer it.
- `d3` — h12 (the job manifest is recorded in the stage manifest) is narrowed to non-local executors: when `distill_executor` is 'local', the train and quantize stage manifests stay byte-identical to main and the job manifest is only returned by `run_train`; any other executor records it under 'jobs' in the stage manifest via executor.`record_job`. Implemented in the decoupling task (d-t16). — Recording it for the local executor adds a 'jobs' key to manifests/train.json and breaks the golden byte-identity success signal c33; the operator chose 'non-local only' over refreshing the golden fixtures or a side file.
- `d4` — The decoupling task (d-t16) also makes jev status compute distill staleness with the same per-run stage inputs the pipeline uses (pipeline.`_stage_for`: bf16 swaps quant calibration and predictions for the select calibration; a skipped corrections-draft drops `CORRECTIONS_FILE` from assemble), so gate, final, edge and assemble are not shown stale on a bf16 run or after a skipped corrections-draft. — t12 left jev status on the static REGISTRY, so c39's 'skipped shows correctly in jev status' is not met for dependents on bf16 and skipped-corrections runs; the operator chose to fold the fix into the decoupling task.

- Operator decisions during speccing (frame, confirmed): Clef and the stock target are mandatory (c23), a bf16 ship is allowed when decided (c24), code is executor-agnostic with SageMaker in a later session, region us-east-1 (c25), and the teacher bar is relative to the served Clef variant (c43).
- t7 kept `example_doc()` at schema v2 and added `example_doc_v3()`, because about 15 test files and the e2e build on the v2 draft — no deviation record covers this; a defensible scoping choice inside t7's criterion.
- t9 renamed the report result `miss` to `fail` (behavioral delta b2) and fixed a latent bug where an unmeasured model scored as all-wrong (b3).
- t10 placed the bf16 skip at the top of `run_quant` rather than in the format decision, because the quant bars would refuse a bf16 pre-registration first.
- t12 found run.toml refuses tables, so a profile is selected only with `distill_student_profile = "<path>"` (no `[student]` table); it also gave `train.run_grid` `executor` and `expected_outputs` parameters (outside its listed files).
